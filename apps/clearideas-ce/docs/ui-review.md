# Clear Ideas CE — UI Review (Vue 3 / Vuetify 4)

Scope: `apps/clearideas-ce/src-web` (123 Vue SFCs, ~16.2k lines; 27 SCSS partials, ~3.1k lines), the web test suite (`test/web`, `test/e2e`) and the supporting build/CI config.

Method: full static read of every layout, view, base component and stylesheet; cross-referencing with the README screenshots; running the repo's own `report-ce-css-usage` / `report-ce-vue-usage` scripts. `node_modules` is not present in the review sandbox and there is no network, so nothing was executed in a browser — findings are code-evidence based and each cites a file/line.

Severity scale

**P0** – visibly broken or blocks users · **P1** – material usability / accessibility / maintainability risk · **P2** – inconsistency or debt worth fixing in a targeted pass · **P3** – polish / hygiene

## 1. Executive summary

The visual language is in good shape: a light, low-chroma surface system, blue primary, pill buttons, generous whitespace, well-considered dark theme tokens. That should be preserved.

Underneath, the UI layer shows the marks of being carved out of a larger product: two parallel theming systems, Pro-only FontAwesome prefixes mapped onto the Free set (with several icons that silently render as nothing), three hand-rolled variants of the same "settings side-nav" layout, filter logic copy-pasted between list and tile views, dead "hero/bookmarks" code paths, a 2.8k-line PDF viewer with a stubbed `t()`, and 248 `!important` declarations holding the cascade together. There is **no lint/format tooling** and the web test suite covers utilities and store contracts but essentially **no rendered components** — every Vuetify component is stubbed away in the existing tests.

The most important user-facing problems are (a) the Inter font is referenced everywhere but never loaded, so the app renders in the OS fallback sans-serif for most users, (b) a custom `IconCheckbox` used for every checkbox in the app that is not keyboard-operable or screen-reader-announced, (c) missing icons, (d) primary actions styled as text buttons with no hierarchy, and (e) several layout/menu controls built from clickable `<span>`/`<VIcon>` instead of buttons.

The recommended approach is a targeted **stabilise → standardise → test** pass rather than a redesign: fix the P0/P1 defects, consolidate duplicated components and CSS behind a small set of documented primitives, and stand up a component-level test harness (Vuetify-mounted Vitest + a11y checks + a few real Playwright flows) so the consolidation is safe.
